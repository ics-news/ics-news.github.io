Part One

Foundations

Chapter 1: How the Web Works

Before writing a single line of code it helps to understand what actually happens when someone types a URL into a browser and a page appears on screen.

Clients and servers

Every website lives on a computer called a server — a machine that is switched on 24 hours a day and connected to the internet. When you open a browser tab and go to a URL, your computer (the client) sends a message to that server saying "please send me the file at this address". The server responds by sending the file back. This conversation follows a set of rules called HTTP (Hyper-Text Transfer Protocol).

What the browser receives

The server sends three types of file:

  • HTML — a text file that describes what is on the page (headings, paragraphs, links, images)
  • CSS — a text file that describes how things look (colours, fonts, spacing, layout)
  • JavaScript — a text file that describes what things do (respond to clicks, animate, fetch data)

The browser reads these files in order, builds an internal model of the page (called the DOM), and paints what you see.

GitHub Pages

For this project, the "server" is GitHub Pages — a free service from GitHub that treats the files in a repository as a website. Every time you push a commit, GitHub rebuilds the site. Changes can take 30–90 seconds to appear, which is why a hard-refresh (Ctrl + Shift + R) is sometimes needed to bypass the browser's own cache.

Chapter 2: HTML — Structure

What HTML is

HTML (HyperText Markup Language) is a language made of tags. A tag is a word wrapped in angle brackets. Tags come in pairs: an opening tag and a closing tag (which has a / before the word). Everything between them is the tag's content.

<p>This is a paragraph.</p>
<h1>This is a large heading.</h1>
<a href="news.html">Go to news</a>

A few tags are self-closing — they have no content and no closing tag:

<img src="photo.jpg" alt="A photo">
<br>   <!-- a line break -->
<hr>   <!-- a horizontal rule -->

Attributes

Tags can carry extra information called attributes, written inside the opening tag as name="value" pairs. Common attributes:

AttributeUsed onMeaning
href<a>Where the link goes
src<img>, <script>File to load
idAny tagUnique name — only one per page
classAny tagReusable label — many elements can share it
styleAny tagInline CSS rules
target="_blank"<a>Open in a new tab
data-*Any tagCustom data you define (see below)

The skeleton of every HTML page

Every HTML file in this project starts the same way:

<!DOCTYPE html>        <!-- Tells the browser: "This is modern HTML5" -->
<html lang="en">      <!-- Root element; lang helps screen readers -->
<head>
  <meta charset="UTF-8">              <!-- Allows all characters -->
  <meta name="viewport" ...>          <!-- Makes layout work on phones -->
  <title>Page Title</title>
  <link rel="stylesheet" href="quiz_styles.css">   <!-- Load CSS -->
</head>
<body>
  <!-- Everything visible goes here -->
  <script src="quiz_script.js"></script>  <!-- Load JS at the bottom -->
</body>
</html>
Why does <script> go at the bottom? JavaScript often needs to find elements in the page. If the script runs before the HTML tags are read, those elements do not exist yet and the script crashes. Placing <script> at the very end of <body> guarantees the whole page is built first.

IDs vs Classes

These two attributes are the main way CSS and JavaScript target specific elements.

  • id — unique. Each ID may appear only once per page. Use it when you mean one specific thing: id="popup", id="quiz-inner".
  • class — reusable. Many elements can share a class. Use it for groups of similar things: class="ideal-node", class="option".
<!-- One unique popup -->
<div id="popup"> ... </div>

<!-- Six nodes, all styled the same way -->
<div class="ideal-node" data-ideal="I">I</div>
<div class="ideal-node" data-ideal="D">D</div>

data-* attributes

HTML lets you invent your own attributes by prefixing them with data-. This is how information is embedded in HTML elements for JavaScript to read later — without polluting the standard attribute list.

<div class="ideal-node" data-ideal="I">I</div>
<div class="discovery-node" data-parent="I" data-name="Diversity Dani"></div>

In JavaScript, every custom data attribute is available through element.dataset. The data- prefix is stripped and hyphens become camelCase:

// data-ideal  →  element.dataset.ideal
// data-parent →  element.dataset.parent
// data-name   →  element.dataset.name

const node = document.querySelector('.ideal-node');
console.log(node.dataset.ideal);  // "I"

Nesting

Tags can contain other tags. The inner tag is called a child; the outer one is the parent. Nesting must be correctly closed — if you open <div> inside <nav>, you must close </div> before </nav>.

<nav class="navbar">
  <a href="index.html" class="nav-brand">ICS News</a>
  <div class="nav-links">
    <a href="news.html">Today's News</a>
    <a href="ideals.html" class="active">Exploring Your IDEALS</a>
  </div>
</nav>

Block vs inline elements

Block elements (like <div>, <p>, <h1>, <nav>) start on a new line and fill the full width available.

Inline elements (like <span>, <a>, <strong>, <em>) flow within a line of text, only as wide as their content.

CSS can override this with the display property.

Chapter 3: CSS — Appearance

What CSS is

CSS (Cascading Style Sheets) is a language of rules. Each rule says: find these elements, then apply these styles to them.

/* selector   { property: value; } */
h1            { color: red;        }
.ideal-node   { border-radius: 50%; }
#popup        { background: white; }

Selectors

SelectorTargetsExample
tagAll elements of that typep { ... }
.classElements with that class.navbar { ... }
#idThe single element with that id#popup { ... }
a:hoverAn anchor while the mouse is over ita:hover { color: red; }
.parent .childA child inside a parent (any depth).nav-links a { ... }
*Every element* { box-sizing: border-box; }

The box model

Every element on a page is a rectangle — even circles. It has four layers:

  1. Content — the text or image inside
  2. Padding — space inside the border, between content and border
  3. Border — a line around the element
  4. Margin — space outside the border, pushing away neighbouring elements
.option {
  padding: 1rem 1.25rem;   /* top-bottom: 1rem, left-right: 1.25rem */
  border:  1px solid #00000015;
  margin-bottom: 0.75rem;
}
Tip: box-sizing: border-box By default, width only measures the content area — padding and border are added on top. Setting box-sizing: border-box makes width include padding and border, which is almost always what you want. That is why the codebase has *, *::before, *::after { box-sizing: border-box; } at the top of the stylesheet.

Chapter 4: JavaScript — Behaviour

What JavaScript is

JavaScript (JS) is the only programming language that runs directly inside a browser. While HTML describes what is on the page and CSS describes how it looks, JavaScript describes what happens — when you click a button, fill a quiz, or watch nodes orbit a centre point.

Comments

Lines beginning with // (single-line) or wrapped in /* ... */ (multi-line) are ignored by the browser. They are notes for developers.

// This is a single-line comment
/* This is a
   multi-line comment */

The console

Open browser DevTools with F12, then click the Console tab. console.log() prints values there — indispensable for debugging.

console.log("Hello, world");
console.log(42);
console.log(someVariable);

Statements and semicolons

JavaScript executes one statement at a time. Statements end with a semicolon ; (optional but recommended). The browser runs them top-to-bottom.

Chapter 5: The DOM — Connecting All Three

What the DOM is

When the browser reads your HTML it builds an internal tree of objects — one object per tag. This tree is called the Document Object Model (DOM). JavaScript can read and change this tree, which is how a page becomes interactive.

Think of the DOM as a live map of the page. Every <div>, <p>, and <button> is a node in the map. JavaScript can find nodes, read their attributes, change their styles, add new ones, or remove them entirely.

Finding elements

getElementById

// Finds the ONE element whose id="popup"
const popup = document.getElementById('popup');

querySelector

// Finds the FIRST element matching a CSS selector
const firstNode = document.querySelector('.ideal-node');
const popupTag  = document.querySelector('#popup-tag');

querySelectorAll

// Returns ALL matching elements as a NodeList (like an array)
const idealNodes     = document.querySelectorAll('.ideal-node');
const discoveryNodes = document.querySelectorAll('.discovery-node');
// idealNodes has 6 items (I, D, E, A, L, S)
NodeList vs Array querySelectorAll returns a NodeList, not a true Array. NodeLists support forEach but not map or filter. If you need those, convert with Array.from(nodeList).

Reading and writing properties

const el = document.getElementById('popup-title');

// Read
console.log(el.textContent);   // the text inside the element
console.log(el.style.color);   // current inline color

// Write
el.textContent = "Internationalism";      // changes the visible text
el.style.color = "#3A7BD5";               // sets inline style
el.style.left  = "100px";                 // moves absolutely-positioned element

classList — adding and removing CSS classes

The cleanest way to change appearance is to add or remove CSS classes that already have styles defined.

popup.classList.add('hidden');     // adds class — popup disappears (display:none)
popup.classList.remove('hidden');  // removes class — popup reappears
popup.classList.toggle('active');  // adds if absent, removes if present
popup.classList.contains('hidden');// returns true or false

In the codebase, the quiz uses this constantly:

// Show a screen
document.getElementById('screen-quiz').classList.add('active');
// Hide a screen
document.getElementById('screen-landing').classList.remove('active');

Creating new elements

// 1. Create the element
const card = document.createElement('div');

// 2. Set its properties
card.className = 'article-card';
card.textContent = 'Hello world';

// 3. Add it to the page (inside some parent element)
document.getElementById('news-grid').appendChild(card);

CSS custom properties from JavaScript

// Sets --node-color on a specific element
node.style.setProperty('--node-color', '#3A7BD5');

// Gets it back (reads from computed style)
getComputedStyle(node).getPropertyValue('--node-color');

Chapter 6: Variables, Types, and Data Structures

Declaring variables

A variable is a named box that holds a value.

const name = "Dani";    // cannot be reassigned
let   score = 0;        // can be reassigned
var   old   = true;     // older style — avoid; use const/let

Rule of thumb: use const by default. Switch to let only when you know you will reassign the value (like a running angle or score counter).

Primitive types

TypeExampleUse case
String"hello", 'world'Text
Number42, 3.14, -1Quantities, angles, scores
Booleantrue, falseOn/off flags
undefined(a variable declared but not assigned)Absence of a value
nullnullIntentional "nothing"

Template literals

Backtick strings let you embed expressions with ${ }:

const name = "Diversity Dani";
const url  = `url("assets/discoveries/${name}.png")`;
// Result: url("assets/discoveries/Diversity Dani.png")

This is used throughout orbital.js to build image URLs and in news.html to build article card HTML strings.

Objects

An object groups related values under named keys:

const ideal = {
  name:  "Internationalism",
  color: "#3A7BD5",
  desc:  "You see the world as one community...",
  discoveries: [
    { name: "Diversity Dani",    desc: "Dani crosses every boundary..." },
    { name: "Communication Cara", desc: "Cara believes the right words..." }
  ]
};

// Read a property with dot notation
console.log(ideal.name);              // "Internationalism"
console.log(ideal.discoveries[0].name); // "Diversity Dani"

The entire IDEALS object in quiz_script.js is a nested object: keys are single letters (I, D, etc.) and each value is an object with name, color, desc, and discoveries.

Arrays

An array is an ordered list of values. Positions start at index 0.

const letters = ['I', 'D', 'E', 'A', 'L', 'S'];
console.log(letters[0]);   // 'I'
console.log(letters.length); // 6

Array methods used in the codebase

forEach — run a function for every item

idealNodes.forEach(function(node, index) {
  // node  = the current element
  // index = its position (0, 1, 2 ...)
  const angle = (index / idealNodes.length) * 2 * Math.PI;
});

map — transform every item into a new array

// Convert array of objects to array of names
const names = data.discoveries.map(function(d) { return d.name; });
// names = ["Diversity Dani", "Communication Cara"]
names.join(' · ');   // "Diversity Dani · Communication Cara"

find — get the first item that passes a test

const discovery = data.discoveries.find(function(d) {
  return d.name === node.dataset.name;
});
// discovery is now the matching object

sort — reorder in place

articles.sort((a, b) => new Date(b.webPublicationDate) - new Date(a.webPublicationDate));
// Sorts newest-first: if the result is negative, a comes first

Object.entries()

const obj = { I: "Internationalism", D: "Democracy" };
Object.entries(obj).forEach(function([key, value]) {
  console.log(key, value);
  // "I" "Internationalism"
  // "D" "Democracy"
});

Ternary operator

A compact if/else: condition ? valueIfTrue : valueIfFalse

const label = score > 5 ? "You passed!" : "Try again";
// Equivalent to:
// if (score > 5) { label = "You passed!" } else { label = "Try again" }

Chapter 7: Functions

What a function is

A function is a named block of code you can run on demand. You define it once, then call it as many times as you like.

// Definition
function greet(name) {
  return "Hello, " + name + "!";
}

// Call
const message = greet("Cara");   // "Hello, Cara!"

Parameters and return values

Functions can accept inputs (parameters) and send back an output (return value). If there is no return statement, the function returns undefined.

Arrow functions

A shorter syntax for functions, common in modern JS:

// Traditional
const square = function(x) { return x * x; };

// Arrow
const square = (x) => x * x;

// Multiple lines need curly braces and explicit return
const clamp = (value, min, max) => {
  if (value < min) return min;
  if (value > max) return max;
  return value;
};

Anonymous functions

Functions used once, inline, without a name. Very common as event callbacks:

popClose.addEventListener('click', function() {
  popup.classList.add('hidden');
});
// The function has no name — it exists only to be called on click

Closures

A function "closes over" the variables in the scope where it was defined — it remembers them even after the outer function has returned. This is how rotationAngle and discoveryAngle persist across animation frames:

let rotationAngle = 0;  // defined in outer scope

function animate() {
  rotationAngle += 0.003;   // animate() closes over rotationAngle
  // ... position elements using rotationAngle
  requestAnimationFrame(animate);
}

animate();
// Each time animate() runs, rotationAngle has the value from last time

Chapter 8: Events and User Interaction

What events are

The browser fires an event whenever something notable happens: the user clicks, moves the mouse, presses a key, or the page finishes loading. JavaScript can "listen" for these events and run a function in response.

addEventListener

element.addEventListener('eventName', handlerFunction);
Event nameFires when...
clickUser clicks the element
mouseoverMouse enters the element
mouseoutMouse leaves the element
keydownA key is pressed
inputValue of an input field changes
DOMContentLoadedHTML is fully parsed (before images load)
loadEverything (including images) has loaded

The event object

The handler receives an event object with details about what happened:

document.addEventListener('keydown', function(event) {
  if (event.key === 'Escape') {
    closeLightbox();
  }
});

onclick attribute vs addEventListener

Both work but addEventListener is preferred because you can attach multiple listeners to the same event and remove them later.

<!-- Older style (inline) -->
<button onclick="startQuiz()">Begin</button>

<!-- Better style -->
document.querySelector('button').addEventListener('click', startQuiz);

Chapter 9: Animation — requestAnimationFrame

Why not setInterval?

setInterval(fn, 16) runs a function every 16 ms — roughly 60 times per second (60 fps). It works but has problems: the interval fires even when the tab is in the background, and it can drift out of sync with the display's own refresh cycle, causing stuttering.

requestAnimationFrame

requestAnimationFrame(fn) asks the browser to call fn just before it repaints the screen. It automatically runs at the screen's refresh rate, pauses when the tab is hidden, and stays perfectly in sync with rendering — producing buttery smooth animation.

function animate() {
  // 1. Update state
  rotationAngle += 0.003;

  // 2. Apply state to the DOM
  idealNodes.forEach(function(node, index) {
    const angle = (index / 6) * 2 * Math.PI + rotationAngle;
    const x = centreX + 180 * Math.cos(angle);
    const y = centreY + 180 * Math.sin(angle);
    node.style.left = (x - 30) + 'px';
    node.style.top  = (y - 30) + 'px';
  });

  // 3. Schedule the next frame
  requestAnimationFrame(animate);
}

animate(); // Start the loop

The loop never terminates on its own — it keeps scheduling the next frame forever. That is intentional: the diagram should spin continuously.

Chapter 10: Trigonometry for Circular Motion

The unit circle

To place a point on a circle, you need its angle (measured in radians) from the centre. Two functions do the work:

  • Math.cos(angle) → horizontal distance from centre (fraction of radius)
  • Math.sin(angle) → vertical distance from centre (fraction of radius)

Multiplying by the radius gives the actual pixel distance:

const x = centreX + radius * Math.cos(angle);
const y = centreY + radius * Math.sin(angle);

Radians vs degrees

JavaScript's trig functions use radians. One full circle = 2 * Math.PI radians (≈ 6.28). A right angle = Math.PI / 2.

const fullCircle = 2 * Math.PI;     // 360°
const halfCircle = Math.PI;         // 180°
const rightAngle = Math.PI / 2;     // 90°

Spreading 6 nodes evenly around a circle

idealNodes.forEach(function(node, index) {
  // Divide the full circle into 6 equal slices
  const angle = (index / 6) * 2 * Math.PI
                - Math.PI / 2      // start at top (12 o'clock) not right (3 o'clock)
                + rotationAngle;   // add the current rotation offset

  const x = centreX + idealRadius * Math.cos(angle);
  const y = centreY + idealRadius * Math.sin(angle);
  node.style.left = (x - 30) + 'px';  // -30 centres the 60px-wide node on x
  node.style.top  = (y - 30) + 'px';
});

Discovery nodes orbiting their parent

Each discovery node orbits around its parent IDEAL node's current position, not around the canvas centre. The parent's live coordinates are stored as node._cx and node._cy each frame:

discoveryNodes.forEach(function(node) {
  const parent = document.querySelector(
    `.ideal-node[data-ideal="${node.dataset.parent}"]`
  );
  const total = parentCounts[node.dataset.parent]; // how many discoveries share this parent
  const angle = (node._localIndex / total) * 2 * Math.PI + discoveryAngle;

  const x = parent._cx + discoveryRadius * Math.cos(angle);
  const y = parent._cy + discoveryRadius * Math.sin(angle);
  node.style.left = (x - 18) + 'px';
  node.style.top  = (y - 18) + 'px';
});

Chapter 11: Cookies — Remembering Users

What cookies are

Cookies are tiny pieces of text the browser stores on the user's computer. They survive page refreshes and even closing the browser (until they expire). The quiz uses a cookie to remember which IDEAL a returning user got, so the welcome-back screen can greet them by name.

Writing a cookie

// Format: "name=value; expires=date; path=/"
function setCookie(name, value, days) {
  const expires = new Date(Date.now() + days * 864e5).toUTCString();
  document.cookie = name + '=' + encodeURIComponent(value)
                  + '; expires=' + expires + '; path=/';
}

setCookie('userIdeal', 'Internationalism', 365);

Reading a cookie

function getCookie(name) {
  return document.cookie.split('; ').reduce(function(result, item) {
    const [key, val] = item.split('=');
    return key === name ? decodeURIComponent(val) : result;
  }, null);
}

const savedIdeal = getCookie('userIdeal');
// Returns "Internationalism" or null if not set

How the quiz uses cookies

// On page load:
const saved = getCookie('userIdeal');
if (saved) {
  // Show "Welcome back" screen
  document.getElementById('returning-ideal-name').textContent = saved;
  showScreen('screen-returning');
} else {
  // Show the start screen
  showScreen('screen-landing');
}

// After the quiz finishes:
setCookie('userIdeal', result.name, 365);

Chapter 12: Fetch API — Talking to the Internet

What fetching is

Sometimes your page needs to load data from a remote server at runtime — not from a local file but from an API (Application Programming Interface) on the internet. The Fetch API lets JavaScript send HTTP requests and receive responses, all without reloading the page.

Promises and async/await

Network requests take time. JavaScript handles this with Promises — objects that represent a value that will arrive in the future. The modern, readable syntax for working with Promises is async/await:

// An async function always returns a Promise
async function fetchArticles() {
  // await pauses execution until the fetch completes
  const response = await fetch('https://content.guardianapis.com/search?api-key=test');

  // .ok is true for 200–299 HTTP codes
  if (!response.ok) {
    throw new Error('HTTP error: ' + response.status);
  }

  // .json() parses the response body as JSON — also async
  const data = await response.json();
  return data.response.results;
}

try / catch

Network requests can fail (no internet, bad API key, server down). try/catch handles errors gracefully:

async function loadNews() {
  try {
    const articles = await fetchArticles();
    renderCards(articles);
  } catch (error) {
    console.error('Failed to load news:', error);
    showErrorMessage('Could not load stories. Try again later.');
  }
}

URLSearchParams

Building query strings by hand is error-prone (spaces must become %20, etc.). URLSearchParams handles encoding automatically:

const params = new URLSearchParams({
  'api-key':   'test',
  'order-by':  'newest',
  'page-size': '20',
  'show-fields': 'headline,trailText,thumbnail,byline',
});

// Add optional parameters conditionally
if (activeSection) params.set('section', activeSection);
if (activeQuery)   params.set('q', activeQuery);

const url = 'https://content.guardianapis.com/search?' + params;
// → 'https://content.guardianapis.com/search?api-key=test&order-by=newest&...'

Rendering fetched data

function renderCards(articles) {
  const grid = document.getElementById('news-grid');
  grid.innerHTML = '';  // clear previous results

  articles.forEach(function(article) {
    const card = document.createElement('div');
    card.className = 'article-card';
    card.innerHTML = `
      <img src="${article.fields.thumbnail || ''}" alt="">
      <h3>${article.webTitle}</h3>
      <p>${article.fields.trailText || ''}</p>
    `;
    grid.appendChild(card);
  });
}

Chapter 13: SVG — Drawing in the Browser

What SVG is

SVG (Scalable Vector Graphics) is an XML-based format for drawing shapes directly in HTML. Unlike a <canvas> (which is a pixel grid), SVG elements remain in the DOM and can be styled and manipulated individually.

Creating SVG elements from JavaScript

SVG elements must be created with createElementNS instead of createElement, because they live in the SVG namespace — a different "world" from HTML:

const svg = document.getElementById('orbit-svg');
const NS  = 'http://www.w3.org/2000/svg';  // the SVG namespace

// Create a circle
const ring = document.createElementNS(NS, 'circle');

// SVG uses setAttribute, not direct properties
ring.setAttribute('cx', 250);           // centre x
ring.setAttribute('cy', 250);           // centre y
ring.setAttribute('r',  180);           // radius
ring.setAttribute('fill', 'none');
ring.setAttribute('stroke', '#00000018');
ring.setAttribute('stroke-width', '1');
ring.setAttribute('stroke-dasharray', '4 6');  // 4px dash, 6px gap

svg.appendChild(ring);

Animating SVG every frame

The discovery rings need to move because their parent IDEAL nodes move. Each frame, the ring's cx and cy are updated to match the parent node's position:

// Every animation frame:
idealNodes.forEach(function(node, index) {
  const angle = ...;
  const x = centreX + idealRadius * Math.cos(angle);
  const y = centreY + idealRadius * Math.sin(angle);

  node.style.left = (x - 30) + 'px';
  node.style.top  = (y - 30) + 'px';
  node._cx = x;
  node._cy = y;

  // Move the ring that orbits this node
  discoveryRings[node.dataset.ideal].setAttribute('cx', x);
  discoveryRings[node.dataset.ideal].setAttribute('cy', y);
});

CSS in Depth

Chapter 14: Selectors, Specificity, and the Cascade

Specificity

When two CSS rules target the same element, the more specific one wins:

  1. Inline styles (style="...") — highest specificity
  2. ID selectors (#popup)
  3. Class selectors (.ideal-node) and pseudo-classes (:hover)
  4. Tag selectors (p, div) — lowest specificity

The cascade

When specificity is equal, the rule that appears later in the file wins. This is why the stylesheet loads fonts at the top and overrides at the bottom.

Pseudo-classes

a:hover { color: var(--text); }          /* mouse is over the link */
a.active { color: var(--gold); }         /* link has the class "active" */
.dot:nth-child(2) { animation-delay: 0.2s; } /* second child only */
.btn-primary:active { transform: scale(0.98); } /* button being pressed */

The !important flag

Chapter 17: Transitions and Animations

Transitions

A transition smoothly interpolates a CSS property between two values — from its old value to its new value — over a specified duration.

.ideal-node {
  transition: border-color 0.2s, color 0.2s, transform 0.2s;
}

.ideal-node:hover {
  border-color: var(--node-color);
  color: var(--node-color);
  transform: scale(1.12);
}
/* When the mouse enters, border-color, color, and scale all animate
   smoothly over 0.2 seconds. When the mouse leaves, they animate back. */

@keyframes

For repeating or multi-step animations, define a @keyframes rule, then apply it with animation:

@keyframes fadeUp {
  from { opacity: 0; transform: translateY(16px); }
  to   { opacity: 1; transform: translateY(0); }
}

/* Apply it: name duration easing delay fill-mode */
.eyebrow {
  opacity: 0;
  animation: fadeUp 0.8s ease 0.2s forwards;
}
/* forwards = keep the final state after animation ends */

@keyframes pulse {
  0%, 100% { opacity: 0.3; transform: scale(0.8); }
  50%       { opacity: 1;   transform: scale(1); }
}

.dot {
  animation: pulse 1.2s ease-in-out infinite;
}
/* infinite = loop forever — used for the loading dots */

animation-delay for staggered effects

.dot:nth-child(1) { animation-delay: 0;    }
.dot:nth-child(2) { animation-delay: 0.2s; }
.dot:nth-child(3) { animation-delay: 0.4s; }
/* Each dot starts its pulse slightly later — creates a wave effect */

Cookie helpers

Two small utility functions wrap the awkward document.cookie API into readable calls:

function setCookie(name, value, days) {
  const expires = new Date(Date.now() + days * 864e5).toUTCString();
  // 864e5 = 86400000 = milliseconds in one day
  document.cookie = name + '=' + encodeURIComponent(value)
                  + '; expires=' + expires + '; path=/';
}

function getCookie(name) {
  return document.cookie.split('; ').reduce(function(result, item) {
    const [key, val] = item.split('=');
    return key === name ? decodeURIComponent(val) : result;
  }, null);
}

Quiz state machine

The quiz is a state machine: at any moment it is in one of five states (landing, returning, quiz, calculating, result). The showScreen(id) function transitions between them by toggling the active class.

function showScreen(id) {

    s.classList.remove('active');

  document.getElementById(id).classList.add('active');

Scoring

Each quiz option carries a weights object that maps IDEAL keys to point values. After every answer, the weights are accumulated. The IDEAL with the highest total wins.

// After each answer:

  scores[key] = (scores[key] || 0) + value;
});

// After all questions:
const winner = Object.entries(scores).sort((a, b) => b[1] - a[1])[0][0];
// Sort descending by score, take the first entry's key

Measuring the container

SVG orbit rings

The dashed rings are drawn with SVG rather than CSS because they need to move each frame. A CSS border stays fixed relative to its element; an SVG circle's cx/cy can be updated programmatically.

Pre-computing discovery counts

Before the animation loop starts, the code figures out how many discoveries each IDEAL parent has. This runs once instead of recalculating every frame.

const parentCounts = {};
discoveryNodes.forEach(function(node) {
  const p = node.dataset.parent;
  if (parentCounts[p] === undefined) parentCounts[p] = 0;
  node._localIndex = parentCounts[p]++;
  // _localIndex is 0 for the first child, 1 for the second, etc.
});
// After: parentCounts = { I: 2, D: 2, E: 2, A: 2, L: 2, S: 2 }

The animation loop in full

let rotationAngle  = 0;   // IDEAL nodes orbit angle — increases each frame
let discoveryAngle = 0;   // Discovery nodes orbit angle — increases twice as fast

function animate() {
  rotationAngle  += 0.003;   // ~1 full revolution every 35 seconds
  discoveryAngle += 0.006;   // discoveries spin at 2× speed

  // ── Position IDEAL nodes ──
  idealNodes.forEach(function(node, index) {
    const angle = (index / idealNodes.length) * 2 * Math.PI
                  - Math.PI / 2        // start at top
                  + rotationAngle;

    const x = centreX + idealRadius * Math.cos(angle);
    const y = centreY + idealRadius * Math.sin(angle);

    node.style.left = (x - 30) + 'px';
    node.style.top  = (y - 30) + 'px';

    // Store live position for discovery nodes to use
    node._cx = x;
    node._cy = y;

    // Move this IDEAL's discovery ring to the same centre
    discoveryRings[node.dataset.ideal].setAttribute('cx', x);
    discoveryRings[node.dataset.ideal].setAttribute('cy', y);
  });

  // ── Position Discovery nodes ──
  discoveryNodes.forEach(function(node) {
    const parentIdeal = node.dataset.parent;
    const parent = document.querySelector(
      `.ideal-node[data-ideal="${parentIdeal}"]`
    );
    const total = parentCounts[parentIdeal];
    const angle = (node._localIndex / total) * 2 * Math.PI + discoveryAngle;

    const x = parent._cx + discoveryRadius * Math.cos(angle);
    const y = parent._cy + discoveryRadius * Math.sin(angle);
    node.style.left = (x - 18) + 'px';
    node.style.top  = (y - 18) + 'px';
  });

  requestAnimationFrame(animate);
}

Chapter 24: GitHub Pages — Publishing

How it works

The repository ics-news/ics-news.github.io is a special GitHub repository. Any files in the main branch are automatically served as a website at https://ics-news.github.io. There is no server to configure — GitHub handles everything.

The deployment cycle

  1. You edit files locally
  2. git add — stage the changed files
  3. git commit -m "message" — save a snapshot
  4. git push — upload to GitHub
  5. GitHub detects the push, rebuilds the site (30–90 seconds)
  6. The site is live

Why changes don't appear immediately

Two layers of caching can make it look like nothing changed:

  • GitHub CDN cache — GitHub serves files through a content delivery network. After a push, it takes 30–90 seconds for the new files to propagate.
  • Browser cache — your browser saves a local copy of recently visited files to load them faster. It may show you the old version even after GitHub has updated.

Fix: wait 60 seconds after pushing, then press Ctrl + Shift + R (hard refresh — bypasses browser cache and forces a fresh download).

Checking what's live

git log --oneline -5
# Shows the last 5 commits — the top one should match what GitHub shows
# under Settings → Pages → "last deployed"
